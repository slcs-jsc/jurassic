# Output radiances and spectra

This page describes the radiance- and spectrum-related output produced
by JURASSIC forward-model and retrieval applications. These outputs are
primarily written to the **observation geometry file** (`obs.tab`) and,
optionally, to additional diagnostic files depending on the application
and configuration.

---

## Overview

In JURASSIC, radiances are always associated with:

- a specific **observation geometry** (line of sight),
- a specific **detector channel** (or spectral band).

As a result, radiance output is stored directly in the observation
container (`obs_t`) and written to disk together with the corresponding
geometry information.

Depending on the workflow, radiances may represent:

- simulated radiances from a forward model run,
- measured radiances used as retrieval input,
- fitted radiances produced during or after a retrieval.

---

## Radiance storage in `obs.tab`

### Radiance columns

In the default ASCII observation format (`OBSFMT = 1`), radiances are
stored in the `rad[]` columns of `obs.tab`.

For each observation (row) and detector channel `i`:

- `rad[i]` contains the channel-integrated radiance.

The total number of radiance columns is therefore equal to `ND`, the
number of detector channels defined in the control file.

### Units

Radiance units are **not enforced by the code** and depend on the
lookup tables and Planck-function normalization used during table
generation.

Typical conventions include:

- spectral radiance (e.g. W·m⁻²·sr⁻¹·cm)
- band-integrated radiance
- brightness-temperature-equivalent radiance

It is the user’s responsibility to ensure **consistent units** across:

- lookup tables,
- forward simulations,
- measured radiance input (for retrievals).

---

## Transmittance output

In addition to radiances, JURASSIC can store **band transmittances**
associated with each detector channel.

In the default ASCII format, these are written as:

- `tau[i]` — total atmospheric transmittance for channel `i`

Transmittances are dimensionless values typically between 0 and 1.

Transmittance output is useful for:

- diagnostic purposes,
- validation against reference models,
- sensitivity studies.

---

## Forward-model output behavior

### Forward simulations

In a pure forward-model run (e.g. using `formod`):

- `rad[]` is **computed by JURASSIC** and written to `obs.tab`,
- `tau[]` may also be written, depending on the application.

Any existing values in the `rad[]` or `tau[]` columns are overwritten.

### Spectral resolution

Radiances are computed at the **detector-channel level**, not on a
fine spectral grid. The effective spectral resolution is therefore
determined by:

- the detector channel definitions (`NU[i]`),
- the spectral windows and lookup tables.

JURASSIC does not output line-by-line spectra in its core configuration.

---

## Retrieval output behavior

In retrieval applications:

- `rad[]` usually contains the **measured radiances** on input,
- the forward model computes simulated radiances internally,
- the final fitted radiances may overwrite or be written alongside the
  input values, depending on the application.

Retrieval tools often write additional diagnostic output (see below)
to allow comparison between measured and fitted radiances.

---

## Brightness temperature output

Some applications support optional conversion of radiances to
**brightness temperatures**.

This behavior is controlled via the control keyword:

- `WRITE_BBT`

When enabled:

- brightness temperatures are computed using the inverse Planck
  function,
- output may be written to auxiliary files or additional columns,
  depending on the application.

Brightness temperature output is primarily intended for diagnostic and
visualization purposes.

---

## Diagnostic and plotting output

The example projects provided with JURASSIC typically include scripts
that:

- compare simulated radiances against reference data,
- generate plots of radiances versus channel or altitude,
- visualize transmittance and contribution functions.

These diagnostics are not generated by the core library itself but are
part of the surrounding project workflow (often using tools such as
gnuplot).

---

## Numerical considerations

- Radiance values are computed using band-averaged emissivities and
  Planck functions.
- Small numerical differences may occur depending on:
  - ray-path discretization,
  - lookup-table interpolation,
  - parallel execution layout.

Such differences are generally negligible for scientific applications
but should be considered when performing bitwise comparisons.

---

## Summary

JURASSIC outputs radiances and transmittances directly in the observation
geometry file, tightly coupling spectral information with the
corresponding viewing geometry.

This design simplifies downstream processing, comparison with
measurements, and integration with retrieval workflows, while remaining
flexible enough to support a wide range of infrared remote sensing
applications.
