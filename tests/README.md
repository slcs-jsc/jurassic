# JURASSIC regression tests

The tests in this directory exercise command-line behavior, file formats,
numerical tools, forward modelling, and retrieval workflows for JURASSIC. Most
suites create a fresh local `data/` directory and compare selected outputs
exactly with checked-in files under `data.ref/`. They are intended to detect
regressions in controlled configurations; they do not by themselves establish
scientific accuracy for other applications or platforms.

## Test catalog

| Suite | Main purpose | Executables or functionality | Important inputs and references | Provenance or generation |
| --- | --- | --- | --- | --- |
| `atm_test` | Atmospheric-profile generation, interpolation, hydrostatic adjustment, and format round trips | `climatology`, `interpolate`, `hydrostatic`, `atmfmt`; ASCII, binary, and netCDF I/O | `atm.ctl`; six atmospheric profiles in `data.ref/` | The compared outputs are generated by the commands in `run.sh`. The script also checks appended profiles directly against outputs from the same run. |

| `ret_test` | Retrievals in directory mode and shared netCDF mode, including diagnostic matrices and error products | `climatology`, `limb`, `formod`, `retrieval`, `atmfmt`, `obsfmt`, `matfmt` | `ret.ctl`; 16 case-0 outputs in `data.ref/`; `tests/data/boxcar_*` lookup tables | Atmospheres, synthetic measurements, retrieval products, and extracted shared-I/O results are generated by `run.sh`. The top-level `tests/data/` directory contains shared spectral filters and
emissivity lookup tables used by the forward-model, matrix, retrieval, and table
I/O tests. File names identify boxcar channels at 792 and 832 cm<sup>-1</sup> and
AIRS-named channels near 668 cm<sup>-1</sup>.

For details of the table format and generation workflow, see
[Emissivity lookup tables](../docs/manual/lookup_tables.md).

## Running the tests

Build and run the complete default regression suite from the repository root:

```bash
cd src
make check
```

`make check` runs `cli_test`, `tools_test`, `atm_test`, `mat_test`, `obs_test`,
`tbl_test`, `formod_test`, and `ret_test`.

The same regression tests are also run automatically by GitHub Actions for
continuous testing and code coverage, and are additionally exercised by the
[JURASSIC nightly builds](https://datapub.fz-juelich.de/slcs/jurassic/nightly_builds).
Local `make check` and automated CI, coverage, and nightly runs
therefore use the same regression tests as part of the project's
quality-assurance workflow.

Run an individual suite from its own directory because the scripts use relative
paths. For example:

```bash
cd tests/obs_test
bash ./run.sh
```

The optional MPI suite can be run through its dedicated build target:

```bash
cd src
make mpi_test
```

Its `run.sh` accepts `NPROF`, `MPI_NTASKS`, `MPI_CMD`, and `OMP_NUM_THREADS`
environment overrides.

For additional guidance on testing and scientific validation, see
[Testing and validation](../docs/manual/validation.md).

## Reference data and reproducibility

Suites with a `data.ref/` directory regenerate results under a temporary local
`data/` directory and use exact `diff` comparisons against the checked-in
references. These comparisons detect changes in numerical output and serialized
text formats. Several round-trip and shared-I/O checks instead compare two files
generated during the same run.

The `run.sh` scripts establish how JURASSIC generates the atmospheric,
observation, radiance, kernel, matrix, retrieval, filter, and derived lookup-table
outputs used in their comparisons. In particular, `tbl_test/run.sh` contains the
commands that generate its 667.5000 cm<sup>-1</sup> filter and CO2 table outputs
from `opt_01000.asc`. The repository does not provide a dedicated command that
promotes generated `data/` files into `data.ref/`, nor does it document the
original creation of every checked-in baseline.

The regression tests also use a small number of precomputed inputs stored
directly in the repository:

- `tests/tbl_test/opt_01000.asc` is a calculation of monochromatic optical depth
  for a 1 km homogeneous path generated externally with RFM 4.28 using
  HITRAN 2008. It is used as input for the lookup-table generation exercised by
  `tbl_test`; no more detailed provenance is available.
- The AIRS and boxcar filters and emissivity tables in `tests/data/` originate
  from external RFM 4.28 calculations using HITRAN 2008. They were imported into
  the repository and processed into JURASSIC lookup tables with the JURASSIC
  `tbl*` tools; no more detailed provenance is available.
- `tests/formod_test/fov.tab` is an idealized trapezoidal field-of-view
  characterization based on the Envisat MIPAS instrument, with a base width of
  4 km and a top width of 2.8 km.

Although the RFM and HITRAN versions used to create the test data are relatively
old, this does not affect their role as fixed inputs for detecting software
regressions. They are intended for technical regression testing, not validation
against current spectroscopy.

When a change intentionally affects a checked-in result, run the relevant
`run.sh`, inspect the generated file against its `data.ref/` counterpart, and
update only the affected reference. Because there is no automated reference
update target, each replacement must be deliberate. Reference changes should be
reviewed together with the code change that causes them and explained in terms
of the affected calculation or format.

## Regression tests versus numerical validation

These suites verify stable behavior for a small set of configurations and I/O
paths. Broader comparisons with other radiative transfer models, sensitivity
studies, and application-specific scientific assessment belong under
`projects/validation/`. Passing the regression suite is therefore a software
consistency check, not a general validation of model accuracy.
